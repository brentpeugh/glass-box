## New findings (beyond the punch list)

**N1 — The "Rule of 40" label defeats the digit guard's own team.** The engine label `Rule of 40` contains a digit. It appears in the efficiency evidence menu handed to the curation model (via `clusterEvidence` → `metricMenu` labels), and the salience fact `"Rule of 40 vs benchmark"` exists in every ranking. Consequence: any *live* thesis that names the metric — which the prompt practically invites, since the label is in the menu — trips `guardFraming`, empties the thesis, renders the curation non-viable, and silently falls back to the deterministic read. Today's top finding is CAC payback so the tripwire fires only occasionally, but it systematically raises the fallback rate on efficiency boards (the default CFO view), and if Rule of 40 ever *leads* (some perturbations would do it), live curation would be rejected ~every draw for correctly naming the finding. There's also an asymmetry a close reader could poke: the deterministic fallback thesis embeds the same label unguarded, so the identical string is forbidden from the model and rendered from the fallback. Fix: before the digit test, strip exact engine-supplied label strings (the menus already enumerate them — they're *references* to engine-named objects, not authored values), then guard what remains. That keeps the invariant philosophically clean: naming an engine metric is referencing, not authoring.

**N2 — Nothing else.** I re-ran the full round-1 adversarial battery against v2: fabricated evidence/test/widget IDs still dropped with the remainder viable; the no-falsifier rejection still fires; the fallback theses (base and perturbed) pass the new stricter guard; salience determinism holds; perturbation still re-derives concentration as the new lead; the dataset is unchanged and clean; the build passes; deployed parity is exact.
